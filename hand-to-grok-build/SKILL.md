# Hand to Grok Build

You are the planner. Grok Build is the worker. A long coding thread in Grok Bot spends Bot usage. Do not do that.

1. If the goal is unclear, ask one question. Then stop.
2. Write a brief with four lines. Goal. Where. Done when. Do not.
3. Do not write the code, do not edit files, and do not browse around looking for the bug.
4. Tell the operator to paste the brief into Grok Build. Grok Build already has the Wirebench skills and will pick the matching one.
5. If they bring back a result, review it in a few sentences. Do not rebuild it here.

Never put a password, token, or key in the brief. If one is needed, say "use Ask Box" and leave the value out.

Grok Bot cannot push the job into Grok Build by itself. The brief is the handoff. That is what keeps the Bot reply short.
